# 架构 {#architecture}

ClientSim 的架构侧重于小型组件，采用基于事件的观察者模式，并结合手动依赖注入，即每个类在初始化时只接收它所需的依赖项。其中包含的玩家控制器基于通用依赖提供者，这使得最终可以扩展到使用 VR，而无需重写核心系统。

## 观察者模式 {#observer-pattern}

ClientSim 使用观察者模式在系统内发送事件，任何对象都可以监听这些事件，而无需知道由谁处理。事件有助于解耦各个系统，提升可测试性：一个系统不必仅仅为了在事情发生时发送消息就与另一个系统直接依赖。具体细节请参阅 [EventDispatcher](runtime/event-dispatcher.md)。

## 依赖注入 {#dependency-injection}

ClientSim 的架构采用手动处理的依赖注入。在创建某个系统时，所有依赖都会传递给它，方式可以是构造函数，也可以是初始化方法。依赖被组织为提供者，并且必须扩展一个声明了它提供哪些方法的接口。当一个类需要某个特定项时，它依赖的是提供者接口，而不是实现该接口的类。这样便可以在不修改依赖方代码的情况下替换提供者的不同实现。提供者模式还使得在测试中轻松模拟依赖成为可能。
