# 可播放图层 {#playable-layers}

当你为 VRChat 虚拟形象创建动画时，你会用到 VRChat 的「可播放图层」（Playable Layers）。它们允许你将可能想对虚拟形象做的某些事情清晰地分离到各自的动画中——例如奔跑、跳跃、点赞、微笑、摇尾巴，以及这些动作的组合。
:::caution 需要 Unity 知识

本文档的编写假定你对 <UnityVersionedLink versionKey="minor" url="https://docs.unity3d.com/<VERSION>/Documentation/Manual/class-AnimatorController.html">Unity 动画器</UnityVersionedLink> 有一定了解。
:::

在 Avatars 3.0 Avatar Descriptor 中，所有 humanoid 虚拟形象都有五个按钮：
- Base
- Additive
- Gesture
- Action
- FX

通用虚拟形象只有三个按钮：
- Base
- Action
- FX

这些就是**可播放图层**。每一个都接收一个 Unity 动画器，并且它们会相互叠加。换句话说，你有五个根动画器可以使用，每个都可以包含多个**动画器图层**。

这些图层的应用是有顺序的——换句话说，先应用 Base，然后 Additive，然后 Gesture、Action、FX。例如，如果 Additive 中的某个东西动画了某根骨骼（权重为 1.0），然后 Action 中的某个东西动画了同一根骨骼（权重为 1.0），则 Action 的动画将优先。

我们在 SDK 中提供了示例可播放图层。根据你学习和迭代的方式，使用并编辑这些默认图层来弄清楚问题可能对你更容易！

它们位于 `Packages/com.vrchat.avatars/Samples/AV3 Demo Assets/Animation/Controllers`。它们的名称与图层名称并不完全对应：

* Base：`vrc_AvatarV3LocomotionLayer`
* Additive：`vrc_AvatarV3IdleLayer`
* FX：`vrc_AvatarV3FaceLayer`
* Action：`vrc_AvatarV3ActionLayer`
* Gesture：`vrc_AvatarV3HandsLayer`

当你运行 VRChat 并穿戴（或查看）Avatars 3.0 虚拟形象时，所有这些可播放图层会组合成一个合并的动画器。此动画器是你虚拟形象的根、主动画器，你可以控制它的任何部分。**这意味着没有任何理由在你的虚拟形象上添加额外的动画器。**

另外，你不应在多个可播放图层中使用同一个控制器。这对某些设置可能有效，但这是**非常**糟糕的做法，并且随着你扩展虚拟形象的功能，会导致重大问题。
:::danger 只能使用动画控制器

我们仅支持在可播放图层槽位中使用动画控制器。不要使用任何其他类型的控制器——你会遇到错误，或将无法上传内容。
:::
这些可播放图层是做什么的？简要版本如下：

**Base：** 应始终播放的内容、对移动做出反应（如移动），或虚拟形象的移动状态（奔跑、下落、蹲伏等）。仅限变换动画。
**Additive：** Base 已在使用、但你想要「添加」到其上的内容——例如呼吸动画。仅限变换动画。
**Gesture：** 由手或表情菜单触发的内容。你也可以将其用于「待机动画」，例如摇尾巴、扇动翅膀或动耳朵。仅限变换动画。
**Action：** 完全覆盖，类似 AV2 的表情动作。仅限变换动画。
**FX：** 与手势相同，但用于*不是*变换位置、旋转或缩放的动画的一切内容。

这很不错，但让我们再深入一些。

## Base

Base 图层包含移动动画，包括行走、奔跑、横移的混合树。它还包括跳跃、下落、快速下落、蹲伏和爬行等动画状态。

请记住，如果你在这里放了东西，你就必须重新定义你的移动动画状态。这相当复杂！看看示例 Base 可播放图层，了解它能有多复杂。

Base 中的动画应_只_影响变换，并且所有图层都应使用虚拟形象遮罩，以确保你只影响适当的变换。

## Additive

Additive 图层用于在 Base 中动画的 humanoid 骨骼之上进行叠加式变换移动——例如可以「叠加」到 Base 图层上的呼吸动画。

**如果你想为非 humanoid 骨骼（如尾巴、耳朵等）添加待机动画，请改用 Gesture！** Additive *专门*用于 humanoid 骨骼。

Additive 图层很特殊，因为它_始终_设置为「Additive」混合。简而言之，如果你有一个在移动中移动的变换，Additive 动画会将其动画「叠加」上去。如果你在 Additive 中对骨骼做疯狂的事情，这可能表现得很奇怪，所以尽量保持它相当轻微。

:::caution Additive 首图层的虚拟形象遮罩会被忽略

第一个图层（基础图层、第 0 层等）的虚拟形象遮罩会被忽略。这是用于内部遮罩目的。你仍然可以遮罩其他图层，但你应用于第一层的任何遮罩都会被忽略。
:::

Additive 中的动画应_只_影响变换。

## Gesture

Gesture 图层用于需要在身体各个部位上单独作用的动画，同时身体其余部分仍在播放底层动画。有点像 AV2 的手势，但应用于身体任何部位。

利用虚拟形象遮罩来确保动画*只*影响你想动画的虚拟形象部位！因此，如果你想让手势参数只为左手/右手制作手型，你就需要在每个图层上遮掉那些手。

此外，如果你想为非 humanoid 骨骼（如尾巴、翅膀、耳朵等）添加「待机」动画——Gesture 就是你应该放它的地方。

Gesture 中的动画应_只_影响变换。

## Action

Action 图层用于在需要完全接管角色时覆盖所有其他图层的骨骼动画。基本上，可以理解为 AV2 的「表情动作」。

此图层**默认混合到零。** 在 Action 图层中做任何事之前，你需要使用[可播放图层控制状态行为](/avatars/state-behaviors#playable-layer-control)在过渡到实际执行的动作之前将该图层混合上来！完成后确保将其混合回零。

Action 中的动画应_只_影响变换。

## FX
FX 是一个**特殊图层。** 在所有其他图层上，你不应使用材质动画、着色器属性动画或形态键动画，因为它们不会被复制到你的镜像克隆。只有变换会。

然而，在 FX 图层中，所有内容都会被复制过去！换句话说，***所有不是 humanoid 变换/肌肉动画的内容都应放入 FX 图层。*** 这包括（但不限于）启用/禁用 GameObjects、组件、材质替换、着色器动画、粒子系统动画等。

第一个 FX 图层中的遮罩默认为空，这会（在虚拟形象初始化时）创建一个默认遮罩，禁用所有 humanoid 肌肉，但启用所有 GameObject 动画。这意味着层级视图中的任何动画都应能工作，不过仍然不建议在此处为变换制作动画。

如果你的手势中有非肌肉动画（例如你的 Gesture <UnityVersionedLink versionKey="minor" url="https://docs.unity3d.com/<VERSION>/Documentation/Manual/class-AvatarMask.html">遮罩</UnityVersionedLink> 底部勾选了一些变换），那么这些相同的变换必须在你的 FX 遮罩中被禁用。这将允许你的 Gesture 动画「透过」FX 图层显示。

:::info 示例

假设你的虚拟形象有以下设置：
- 你的虚拟形象上有一条尾巴（一条不属于 humanoid 层级结构的骨骼链）。
- 你用于尾巴的 Gesture 动画器图层有一个特殊遮罩，仅启用该骨骼链。
- 你的另一个带「全部位遮罩」的 Gesture 动画器图层也勾选了那些骨骼（以及控制器其余部分中动画的其他身体部位）。

在这种情况下，你还需要在第一个 FX 图层中创建一个自定义遮罩。这将遮掉所有肌肉（human 图示全红）并遮掉尾巴中的所有骨骼。
你还需要确保此遮罩对任何你要为 FX 制作动画的组件所在的变换打开复选框。例如，用于为形态键或材质制作动画的身体蒙皮网格。

:::

请注意，如果你的层级视图中有同时具有动画变换（在 Gesture 中）和动画效果组件（在 FX 中）的游戏对象，这将不符合遮罩的要求。如果你在层级视图中嵌入了简单静态网格并在 Gesture 中为它制作动画，同时在 FX 中为它应用材质更改，就可能出现这种情况。另一个例子是把粒子效果组件直接放在上面示例的尾巴骨骼上。简单的变通方法是创建一个子游戏对象，将静态网格或效果放在其上。你不会为该子对象的变换制作动画，只对父对象。如果遵循这些步骤，你应无需在 FX 图层中放置变换动画。

## 附加姿势 {#additional-poses}
还有一些可用于 Avatars 3.0 虚拟形象的附加姿势。这些按钮位于可播放图层下方。

### T-Pose
你现在可以提供自己的 T-Pose！

T-Pose 用于确定虚拟形象的各种测量值，尤其是你的视点（或视球）的放置。视点完全取决于当你处于所提供的 T-Pose 动画中时视球的位置。

![标准 T-Pose - [Mixamo](https://www.mixamo.com)](/img/avatars/playable-layers-1.png)

其次，它对于手腕对齐/扭转很重要。你的手腕相对于手掌朝下姿势的排列方式，将影响你的控制器在空间中扭转时如何转动手腕和手臂。

最后，你的 t-pose 决定你的臂展——你在 T-Pose 时手臂的完整长度。这也会决定你的虚拟形象的瞳孔间距（IPD），即你虚拟形象双眼之间的距离。手臂太长会让你的 IPD 更宽，使一切看起来更小。手臂太短会让你的 IPD 更窄，使一切看起来更大。

此外，T-Pose 中（明显的）关节弯曲并不是好事。例如，如果你的肘部在 T-pose 中弯曲，这可能会影响虚拟形象依赖你身体比例的许多不同方面。

### IK 姿势 {#ik-pose}
IK 姿势用于确定主要关节弯曲。在 IK 姿势中，你的关节应在其预期弯曲的方向上略微弯曲。

例如，VRChat 会查看 IK 姿势中的肘部弯曲，并确定在任意方向上是否存在角度弯曲。该弯曲决定你的肘部如何弯曲。

脚在 IK 姿势中的旋转将决定膝盖如何弯曲。其设置方式是：首先假定膝盖将相对于虚拟形象笔直向前弯曲，然后将该方向保存为相对于 IK 姿势中脚部旋转的方向。例如，如果在 IK 姿势中脚尖朝外，这意味着脚的内侧边缘更朝向正前方，因此膝盖将朝脚的内侧边缘弯曲。相反的情况，如果在 IK 姿势中脚更朝内，则脚的外侧边缘更朝向正前方（相对于虚拟形象的正前方方向），因此在这种情况下膝盖会倾向于朝脚的外侧边缘弯曲。

简而言之：如果你想让膝盖更向内弯曲，就在 IK 姿势中将脚向外旋转。如果你想让膝盖更向外弯曲，就在 IK 姿势中将脚向内旋转。

### 坐姿 {#sitting-pose}
此槽位中使用的控制器同时用于动画和摆姿势。当你坐下时，虚拟形象的视点用于校准。播放动画，允许你创建「坐下」动画以及「坐着」的待机动画。

如果你想自己制作，郑重提醒：这可能需要大量调整才能做对！你可能想为坐下/站起使用过渡状态，这能在坐下时略微改善虚拟形象的外观。
